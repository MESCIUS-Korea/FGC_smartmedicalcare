# AI 스마트 진료 안내 (Smart Clinic Guide AI)

환자가 증상을 자연어로 설명하면 AI가 적합한 진료과를 추천하고, 응급 신호가 감지되면 즉시 안전한 안내로 전환하는 병원 진료 안내 시스템입니다. Forguncy의 **AI 대화 셀**과 **함수(Function)** 기능으로 구현되었습니다.

⬇ **[Forguncy 프로젝트 파일 다운로드 (smartmedicalcare.fgko)](https://github.com/MESCIUS-Korea/FGC_smartmedicalcare/raw/main/smartmedicalcare.fgko)**

> 다운로드한 프로젝트 파일에는 AI 모델 연결(API 키) 정보가 포함되어 있지 않습니다. 직접 발급받은 API 키를 Forguncy 빌더> 파일 > 옵션 > 응용 프로그램 설정에서 등록한 후 실행해주세요.

## 핵심 설계 원칙

> **AI는 대화만 하지 않습니다. 함수를 통해 실제 데이터를 조회하고, 그 결과를 직접 저장합니다.**

| 상황 | 처리 방식 |
|---|---|
| 증상을 듣고 진료과를 판단 | AI가 스스로 판단해 함수 호출 여부 결정 |
| 진료과 정보 조회 | 함수 안에서 **진료과마스터** 테이블을 실제로 조회 (AI가 지어내지 않음) |
| 응급 신호 감지 | 별도 함수로 분리, **고정된 안내 문구**를 그대로 전달 (AI가 표현을 바꾸지 않음) |
| 상담 결과 기록 | 함수가 호출되는 시점에 **상담기록** 테이블에 자동 저장 |

AI가 응급 상황에서 매번 다른 표현을 쓰면 위험하기 때문에, 응급 안내만큼은 함수 반환값을 고정 문구로 강제합니다.

## 페이지 구성

### 1. 챗봇 메인
AI 대화 셀 하나로 구성된 환자용 상담 화면입니다. 멀티턴 대화(이전 맥락 기억)가 기본 지원되며, 증상 설명이 불충분하면 AI가 한 번 더 되묻고, 충분한 정보가 모이면 함수를 호출해 진료과를 안내합니다.

### 2. 진료과 입력
`진료과마스터` 테이블을 관리하는 리스트뷰 페이지입니다. 진료과명, 대표 증상 키워드, 진료실 위치, 안내문구를 등록해두면 챗봇 함수가 이 데이터를 그대로 조회합니다.

### 3. 상담기록 조회
AI가 자동 저장한 상담 기록을 의료진이 확인하는 페이지입니다. AI 추천 진료과와 긴급도를 보고, **확정진료과를 의료진이 직접 선택해 저장**하는 구조로, AI의 추천과 최종 확정을 명확히 분리합니다.

## 데이터 테이블

| 테이블 | 주요 필드 |
|---|---|
| `진료과마스터` | 진료과코드, 진료과명, 대표증상키워드, 진료실위치, 안내문구 |
| `상담기록` | 상담번호, 상담일시, 증상요약, 추천진료과, 긴급도, 만족도, 확정진료과 |

`확정진료과`는 AI가 채우지 않습니다. 상담기록 조회 페이지에서 의료진이 직접 선택하는 필드입니다.

## AI 대화 셀 함수 구성

### `recommendDepartment` — 진료과 추천
| 항목 | 내용 |
|---|---|
| 호출 조건 | 증상 부위·양상·기간 중 2가지 이상이 파악되었을 때 |
| 매개변수 | `department_name`(텍스트), `symptom_summary`(텍스트) |
| 명령 ① | 파라미터 설정 `deptInfo` — 진료과마스터에서 `진료과명 = department_name` 조회 |
| 명령 ② | 데이터 테이블 업데이트하기 — 상담기록에 `symptom_summary`, `department_name`, 긴급도="일반" 추가 |
| 반환값 | `location` — 조회된 진료실 위치 |

### `flagEmergency` — 응급 감지
| 항목 | 내용 |
|---|---|
| 호출 조건 | 가슴 통증, 심한 호흡곤란 등 응급 신호가 조금이라도 보일 때 (애매하면 이쪽으로 판단) |
| 매개변수 | `symptom_summary`(텍스트) |
| 명령 | 데이터 테이블 업데이트하기 — 상담기록에 긴급도="응급"으로 추가 |
| 반환값 | `guidance` — 고정된 응급 안내 문구 (AI가 임의로 표현을 바꾸지 않고 그대로 전달) |

## 시스템 프롬프트 설계 시 유의사항

- `recommendDepartment`의 `department_name`은 반드시 **진료과마스터에 실제로 존재하는 이름 중에서만** 고르도록 지시해야 합니다. 목록에 없으면 "가장 가까운 진료과"를 선택하게 하고, 목록 자체도 충분히 폭넓게(내과·외과·산부인과 등 표준 진료과 기준) 구성해야 합니다.
- 되묻기는 **최대 1회**로 제한해야 합니다. 제한이 없으면 정보가 다 모여도 계속 되묻는 문제가 발생할 수 있습니다.
- `flagEmergency`가 반환한 `guidance` 문구는 AI가 그대로 전달하도록 명시해야 합니다.

## 실행 방법

1. [Forguncy 디자이너](https://www.mescius.co.kr/forguncy/download) 설치
2. `smartmedicalcare.fgko` 파일을 디자이너에서 열기
3. 파일 > 옵션 > 응용 프로그램 설정에서 AI 모델(OpenAI 등) 연결 — API 키 직접 등록 필요
4. 챗봇 메인 페이지의 AI 대화 셀에서 방금 등록한 모델 선택
5. 미리보기 또는 게시로 실행
